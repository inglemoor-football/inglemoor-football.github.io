How this site works — for whoever comes next

The short version

The whole website is one file, index.html, sitting in a GitHub repository. There is no database, no login, no hosting bill. GitHub publishes it for free every time the file changes.

Where it lives

  • Repository: github.com/inglemoor-football/inglemoor-football.github.io
  • Site: inglemoorfootball.com
  • Cost: nothing, apart from the domain renewal at GoDaddy

Changing the site

Everything editable sits in a block called SITE in the first 200 lines of index.html — schedule, coaches, board, sponsors, links. Each part is commented. Edit it on github.com or with GitHub Desktop, commit, and it is live in about a minute.

What updates itself

  • Team calendar — pulled from the football Google Calendar every hour by a GitHub Action. Change the calendar and the site follows.
  • Game states — the countdown, the "in progress" badge and the "score pending" note are all worked out from kickoff time. Nobody triggers them.
  • Record and standings — calculated from the scores. Post a score and the record, the colours and the next-game countdown all follow.

What needs a person

  • Final scores — this page
  • Rosters, coach changes, sponsor logos
  • The domain renewal, currently paid through August 2034

If something breaks

A blank page almost always means a missing quote or comma in index.html. Every version ever saved is kept: open the file on github.com, click History, find the last good one, and copy it back. Nothing is ever really lost.

This page

It talks to a small program on Cloudflare that holds the key to the repository. That program will only change the two score numbers on a game that already exists. It cannot edit anything else, which is deliberate — a shared password should not be able to rewrite the website.
